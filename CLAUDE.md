## Commands

- `npm run dev`: start the dev server at http://localhost:3000. It also rewrites the Next.js block in `AGENTS.md`.
- `npm run build`: production build. Also runs the TypeScript type check.
- `npm run lint`: ESLint (flat config in `eslint.config.mjs`, Next core-web-vitals and TypeScript presets). Lint one file with `npx eslint src/app/page.tsx`.
- There is no test runner yet.

## Stack and configuration

- Next.js 16.4 (App Router, Turbopack), React 19.3, TypeScript strict, Tailwind CSS v4. Your built-in knowledge of Next.js may be out of date. Read the bundled docs in `node_modules/next/dist/docs/` (`01-app/`, `03-architecture/`) before using a Next API.
- `next.config.ts` turns on `cacheComponents` and `partialPrefetching`. With Cache Components, data fetching and caching follow the `"use cache"` / Suspense model, not the older `fetch` cache options or `export const dynamic` segment config. Check the docs before adding caching or route segment options.
- Tailwind is wired in through the `@tailwindcss/turbopack` loader rule in `next.config.ts`. There is no PostCSS config. Theme tokens are defined in `src/app/globals.css` using `@theme inline`.
- Typed route helpers such as `LayoutProps<"/">` and `PageProps` are globals generated by Next (`.next/types`). Don't import them.
- Import alias: `@/*` maps to `src/*`.

## Product context

The app is still the create-next-app scaffold. `docs/PRD.md` is the source of truth for what to build: roles, user stories with acceptance criteria, and what belongs in Version 1 versus Version 2. Requirements that affect architecture:

- **The agent never changes anything directly.** It is built on the Claude Agent SDK, with tools to read the calendar, look up goals and suggest time blocks. Every change it proposes is stored as a pending item in an approval queue, and only a user approval applies it. Version 1 has read-only Google Calendar access, so approval only records the decision. Calendar writes come in Version 2.
- **Everything the agent does is audited.** Each agent read, suggestion and user decision is written to an append-only audit log that only its owner can see.
- **Coaches can only see goals.** A coach (Version 2) can see goal progress and comment, and nothing else: no calendar, approval queue, brief or audit log. This must be enforced on the server.
- **Version 2 also adds** a daily brief generated by Vercel Cron, and possibly read-only Gmail access.
